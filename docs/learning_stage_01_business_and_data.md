# 阶段01：业务与数据

本页命令均在项目根目录执行，`python`指本项目独立环境；未激活时用 `.\.venv\Scripts\python.exe` 替代。代码中的教学小例子不用于业务结论。

## 要理解的问题

首先把业务问题拆成四层：发生了多少出行、哪些时段与区域最集中、下一小时会发生多少记录、有限服务名额怎样分配。前三层分别对应描述、诊断和预测，第四层属于假设下的决策模拟。数据不包含未下单乘客、真实可用车辆或完整空驶轨迹，所以不能把订单热度等同于供需缺口。

## 本项目的做法

阅读 data/source_manifest.json 和 TLC 字段字典。每月文件是一张行程表，每行没有公开唯一订单号；位置是 Taxi Zone 编号，里程原单位是英里，金额是美元。区域1是 Newark Airport，属于地图服务区域，并非纽约五个行政区。264与265是未知或无法映射区域，单独统计。2025新增 cbd_congestion_fee，不能丢掉新费用字段。

## 自检练习

练习：不打开代码，解释已记录上车量、计价车费、乘客总支付、小费与平台收入的区别。项目只分析前四者，不能把总支付声称为平台收入。

## 动手步骤与检查点

1. 在项目根目录运行 `python -m src.run_pipeline --stage download --seed 42`。首次下载时观察 logs/download.log；后续读取缓存仍需文件身份检查。
2. 打开 source_manifest.json，按 kind=trip 筛选：必须有2025-01至2025-12共12个文件，每个都有来源、下载时间、字节数、SHA256、行数和字段。自行计算的SHA256是版本身份，不是发布者签名。
3. 对照字典区分 PULocationID 与 DOLocationID、fare_amount 与 total_amount。不要用一个区域字段代替上车和下车两种业务方向。
4. 检查天气365个日历日和纽约代表点坐标。ERA5是事后再分析，不能当作预测时已经知道的天气。

练习答案：上车量是已记录行程数量；计价车费是行程计价部分；乘客总支付还含税费、附加费及已记录小费。数据没有企业收入分成，不能直接算平台收入。现金小费未被完整记录。

交付检查：缺少任何一个月时，全年分析应报错，不能在代码里用演示样本顶替。下载失败可重试；完整清单和缓存身份不符时应先调查数据版本。
