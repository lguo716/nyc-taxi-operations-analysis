# 阶段04：运营诊断

本页命令均在项目根目录执行，`python`指本项目独立环境；未激活时用 `.\.venv\Scripts\python.exe` 替代。代码中的教学小例子不用于业务结论。

## 要理解的问题

先看月度、星期与小时，再定位区域和路线。年度增长并不自动等于同店增长；区域记录量高并不能证明供给不足。把记录量、每笔计价车费、行程时长、质量标记率一起看，才能区分规模、单笔特征和数据可靠性。机场有固定费率与不同出行距离，不能直接把高车费解释为异常。

## 本项目的做法

图表统一标注2025范围、美元/公里/分钟单位及有效样本。天气比较使用纽约代表点的ERA5日度再分析：按月份和星期分层报告均值与天数，避免雨天多发生在不同季节造成表面差异。全年分组图仍有节假日、活动和乘客结构混杂，不能用来证明天气的因果效应。

## 动手步骤与检查点

运行 `python -m src.run_pipeline --stage analyze --seed 42`。依次读取 monthly_metrics、weekday_hour、zone_metrics、route_monthly、daily_metrics、weather_strata，先说明单位和分母，再陈述规律。

月度合计适合描述规模；日均值适合比较不同天数的月份；星期×小时全年合计包含各星期出现次数的差异。工作日、周末、节假日采用互斥分类，节假日优先，不能将同一天重复放进两个组后相加。

天气分析先在同月同星期内计算平均需求，再将每日需求除以该均值，最后按天气分组。查看每组天数，23个降雪日与235个无明显降水日的精度不能直接视为相同。天气、节日和活动仍可能互相混杂。

练习参考：JFK的平均距离和车费高，应结合机场行程结构解释；曼哈顿热点的记录集中，可以提出“高峰小时是否有供给缺口”假设，但验证需要真实车辆可用量和未满足请求，当前数据不足以作结论。
