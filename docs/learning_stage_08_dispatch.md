本页命令均在项目根目录执行，`python`指本项目独立环境；未激活时用 `.\.venv\Scripts\python.exe` 替代。代码中的教学小例子不用于业务结论。

## 要理解的问题

模拟单位是每小时可服务订单名额，默认1000，另比较500和2000。它不是车辆数：真实车辆可能一小时完成多单，也可能正在途中。没有车辆位置和跨区移动成本时，模拟只能回答给定名额如何分配的静态问题。

## 本项目的做法

均匀策略每区相同权重；历史策略取过去四周同星期同小时均值；预测策略取验证选定方案预测量。按比例分配后先向下取整，再按小数余数从大到小补齐；同分按区域编号排序。所有预测为零时回到均匀分配。实际覆盖=min(观察记录,名额)，未覆盖与闲置都非负且守恒。

## 自检练习

练习：把三地区权重设为[0,0,0]、总名额2，说明谁获得名额以及为何。然后读取真实simulation_summary.csv，解释为何模拟收益不能写为真实成本节省。

## 动手步骤与检查点

运行 `python -m src.run_pipeline --stage simulate --seed 42`；检查 simulation_summary.csv 及逐小时明细。名额整数化必须逐小时完成，而不是先按月分配一个总预算。

```python
from src.simulate import allocate
# 教学输入，区域顺序为3、1、2。
print(allocate([0, 0, 0], 2, [3, 1, 2]).tolist())  # [0, 1, 1]
```

练习答案：零预测回退后权重相同，两个名额归编号1与2。同样，小数余数并列时也按区域编号排序。每小时要满足 Σ名额=B、覆盖+闲置=名额、覆盖+未覆盖=实际，不能只对全月总数作弱检查。

历史方案随预测时点滚动取已结束的四个对应小时。即使预测WAPE较好，覆盖可能只略有改善，因为总名额、区域权重和整数化共同决定覆盖。优先报告预测相对历史的差额，再解释均匀分配为何可能较弱。

业务落地还需车辆状态、服务时长和跨区移动约束；本次静态名额模拟没有这些输入。
